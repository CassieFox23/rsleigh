# rsleigh v0.6.1 release notes

A patch release with two fixes on top of [v0.6.0](v0.6.0.md). Install the
[v0.6.1 CLI](https://crates.io/crates/rsleigh/0.6.1) with:

```bash
cargo install rsleigh --version 0.6.1 --locked
```

Prebuilt archives for macOS (arm64/x86-64), Linux glibc (arm64/x86-64), and
Windows x86-64 are on the
[v0.6.1 release page](https://github.com/ShaneBreazeale/rsleigh/releases/tag/v0.6.1),
each with a SHA-256 checksum.

## Fixed

- **Reproducible decoders.** `rsleigh-generate` output is byte-identical
  across runs. Token readers and pattern operand lists used to be emitted in
  hash-map order, so two builds of the same source differed. Each build was
  self-consistent, but its generated sources could not be compared or
  reproduced.
- **Large jump tables print every case.** A recovered table with more than
  about 250 entries used to stop early with an empty `default`; Debian
  `ls`'s 277-entry table stopped after case 253. The structurer now emits
  one `switch` for the whole dispatch chain, and entries that share a target
  share one case body.

## Migration

None. Schemas, evidence identity, and flags are unchanged from 0.6.0. The
generated decoder crates differ textually from 0.6.0's because their
emission order is now fixed. The change reorders declarations only, and the
regression suites and agent corpus give the same results.

## Publication

1. CI passes on the release commit.
2. All 13 publishable crates are published in the order in
   [publish-all.sh](../../scripts/publish-all.sh).
3. The tag `v0.6.1` triggers the
   [release workflow](../../.github/workflows/release.yml), which attaches
   the five platform archives and their checksums.
